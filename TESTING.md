# Стратегия проверок

Владелец технической стратегии — ARCHITECTURE.md. Этот файл содержит её матрицу приёмки, а не новые финансовые или security-правила. Ожидаемые суммы — BUSINESS_RULES.md; доступ — SECURITY.md; факт выполнения — TASKS.md.
Состояние: PHASE 0 начата, P00.1 проверяет каркас; test runner и тесты приложения запланированы в P00.2. Результаты проверок — TASKS.md.

## Уровни и обязательные сценарии
| Область | Unit: Vitest | Integration: настоящая PostgreSQL | E2E / AI |
|---|---|---|---|
| Деньги / формулы | Decimal, scale, переполнение, отрицательные/невалидные значения, ROUND_HALF_UP ±1.005, 100/3, сохранение суммы распределений, контрольные примеры | NUMERIC round trip строкой, запрет NaN/Infinity, journal balance, итоги деталей = отчёт | Ввод/форматирование/экспорт без float |
| Зарплата | Оклад/часы/дни/сделка/комиссия, частичная оплата, 45400−10000=35400, смена ставки, аванс без двойного расхода | Повтор расчёта/проведения, обязательства и выплаты, версии правил/источников | Собственный листок и закрытые зарплаты; локализация до её применения |
| Tenant / permissions | Пары action+scope, SELF, делегирование, ограниченные проекции | Минимум два бизнеса и три пользователя, один участник обоих с разными ролями; RLS/runtime, подмена UUID/FK, pool reuse, bootstrap, последний OWNER, отзыв прав и гонки | Прямой URL, переключение бизнеса, приглашение, отсутствие чужих данных |
| Payments / debts | Аванс ≠ выручка, cash flow ≠ profit, частичные погашения, возврат ≠ сторно | Два соединения конкурируют за один остаток; idempotency same/different payload, rollback после каждого шага, поздний платёж и исторический долг | Timeout → проверка исходной команды, без второго платежа |
| История / даты | Date vs timestamp, timezone/DST, понедельник, месяц/год, dueDate, округление/сторно | Закрытие периода одновременно с проведением; оригинал+сторно по разным датам; audit failure откатывает мутацию | Пользователь видит дату признания/платежа и причину корректировки |
| Inventory / производство | Средневзвешенная оценка, 2220, частичный выпуск, распределение труда/потерь | Параллельное резервирование, отрицательный остаток, финансовая/складская сверка | Прибыль при неизвестной стоимости явно неполна |
| AI / файлы / worker | Валидация tool arguments, привязка чисел к фактам, classification READ/DRAFT/WRITE/DESTRUCTIVE | Те же permissions что HTTP, истёкшие факты, actor revoke, outbox retry, закрытые файлы, audit projection | Prompt injection, скрытые зарплаты, чужой tenant, отказ API, неподтверждённые числа |

Integration tests не заменяются моками SQL или SQLite. Тесты запускаются на одноразовой dev/test БД с реальными миграциями, отдельными runtime/auth/worker ролями; migration-роль только готовит схему. Проверки гонок используют отдельные соединения и управляемые барьеры, а не случайные sleep.
Внешние SDK/почта/storage/LLM в обычном CI подменяются на границах адаптеров. Никаких production credentials или реальных финансовых данных. Модельный eval с внешним API — отдельная проверка P14.1/P14.5 с согласованным бюджетом и синтетическими фактами.
Unit покрывает детерминированную domain-логику; серверные сценарии и async UI проверяются integration/E2E, без попытки подменить всё снимками компонентов. Тесты должны обнаруживать неверный результат/доступ/откат, а не повторять код реализации.

## Процедура
После задачи с кодом: typecheck, lint, связанные тесты. При изменении SQL/permissions/финансов обязательны затронутые integration tests.
После каждой PHASE: typecheck, lint, весь существующий unit/integration/AI suite, существующий Playwright suite, production build. Нельзя исключить упавший suite ради завершения.
В будущем CI: установка по frozen lockfile → подготовка изолированной БД/миграции → проверки → build. Отсутствующие env/БД/браузер дают NOT RUN/FAIL с причиной, не молчаливый skip. Пустой suite не PASS.
Начальное покрытие P00.2 — env validation; P00.3 — Money. Тестовые критерии следующих фаз добавляются вместе с функцией. Универсального процента coverage вместо проверки инвариантов нет.
Документация сейчас: UTF-8/ссылки, согласованность source of truth, целочисленная/decimal сверка примеров, gitignore с положительными и отрицательными примерами, безопасное содержимое файлов и полный diff. Для документационных правок прикладные проверки могут быть N/A с причиной; для каркаса P00.1 результаты typecheck/build и отсутствующих lint/tests фиксируются отдельно в TASKS.md.

## SITE-01: реальные проверки
typecheck проверяет src/tests и отдельный Worker tsconfig; lint — ESLint без warnings. pnpm test пересобирает static UI/Worker и использует отдельную локальную D1 .wrangler/test-state, не production. Playwright desktop/mobile проверяют WebGL/controls/fallback/reduced motion, отсутствие горизонтального overflow, три состояния BUSINESS_RULES §5, страницы terms/privacy/contact/404, signup/reload/logout/login/password/delete/session isolation, server consent/origin/body restrictions и persistent rate limits. Тестовые пароли случайны и не печатаются, trace выключен; screenshots исключены из Git. Фактический PASS/DONE — только TASKS.md после запуска.

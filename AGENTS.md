# Codex: правила проекта

Текущую разрешённую задачу и результаты проверок брать из TASKS.md и последней команды пользователя. Не запускать следующую фазу автоматически.

## Source of truth
Сначала изучить проект: прочитать PROJECT.md, ARCHITECTURE.md, BUSINESS_RULES.md, SECURITY.md, AI_RULES.md, TASKS.md и DECISIONS.md. Затем загружать только связанные код, документацию и зависимости текущей задачи; найти существующие аналоги.
- [PROJECT.md](PROJECT.md) — продукт, пользователи, функции и требования.
- [BUSINESS_RULES.md](BUSINESS_RULES.md) — финансовые формулы, зарплата, прибыль, долги и себестоимость.
- [SECURITY.md](SECURITY.md) — authentication, authorization, permissions, tenant isolation и опасные действия.
- [ARCHITECTURE.md](ARCHITECTURE.md) — техническая структура и границы слоёв.
- [DATABASE.md](DATABASE.md) — структура БД, ключи, связи и ограничения.
- [AI_RULES.md](AI_RULES.md) — AI tools, ограничения ИИ и полный порядок работы.
- [TASKS.md](TASKS.md) — задачи, фазы, статусы и результаты проверок.
- [DECISIONS.md](DECISIONS.md) — решения, причины, альтернативы и последствия.
Команды и инструменты — [README.md](README.md); матрица проверок — [TESTING.md](TESTING.md).
Приоритет предметный: архитектура не переопределяет финансовые или security-правила. При конфликте записать оба утверждения, последствия и затронутые части в DECISIONS.md/TASKS.md; зависимую работу остановить до явного решения, не выбирать вариант автоматически.

## Рабочий цикл
Inspect → Plan → Implement → Verify → Diff → Document → Report.
До каждой задачи сообщить цель, причину, создаваемые/изменяемые файлы, влияние на БД/API, риски и проверки.
Одна задача — одна цель; большие задачи делить. Минимальные изменения без ненужного переписывания, дубликатов и общего refactor.
После задачи с кодом: typecheck, lint, связанные tests; после PHASE — typecheck, lint, полный test suite и production build. Ошибка проверки блокирует DONE; отсутствие проверки не PASS.
Для документов без кода: согласованность, ссылки, gitignore и git diff --check; проверки приложения N/A с причиной.
Проверить git diff, git diff --stat и git status, включая новые файлы; объяснить неожиданные изменения.
Git: main и при необходимости короткие feature branches; небольшие понятные коммиты по README.md.
Обновить TASKS.md: TODO / IN PROGRESS / BLOCKED / DONE; важные решения — DECISIONS.md. Отчёт по AI_RULES.md.
Не начинать следующую большую PHASE, пока текущая не работает и не проверена.

## Инварианты
TypeScript strict; any только с серьёзной записанной причиной. UI, domain, database, services, validation, AI и permissions разделены.
Все внешние данные валидировать сервером. Личность и права выводить из сессии: user → membership → business → permission; клиентским IDs/ролям не доверять. Multi-tenant isolation обязательна во всех слоях, включая AI, файлы, кэши и фоновые задания.
Финансы: детерминированный backend, Decimal/NUMERIC, никаких JS float; атомарные операции с аудитом и сохранением истории.
Продуктовый AI не получает прямого доступа к БД/SQL: только разрешённые tools READ/DRAFT/WRITE/DESTRUCTIVE через серверные сервисы; любой WRITE требует подтверждения, MVP только читает.
Никаких production mocks, пустых catch и бессмысленных TODO/FIXME/HACK. Временное решение — задача и срок исправления в TASKS.md.
Секреты — только env/secret storage, никогда код, Git или вывод. .env.example без секретов; изменения БД только migrations.
Без явного разрешения запрещены reset --hard, clean -fd, force push, удаление рабочих веток/БД, массовое удаление данных, изменение production БД/секретов.
MCP/skills/значимые зависимости: сначала необходимость, аналоги, поддержка, права и риски; не устанавливать автоматически.
